# Apple Music Duplicate Finder v1.1.0

This release improves scan control, reliability, and verification while keeping the existing toolbar popup and exact identifier-based duplicate matching. It remains read-only: playlist data is processed locally, and the extension never removes or changes your music.

## What's New

- **Playlist scan cancellation.** Use **Cancel scan** to stop a scan and start again. Late replies from an earlier scan cannot overwrite a later result.
- **Scan deadlines and clear failures.** Scans have a five-minute overall deadline in addition to the existing per-request timeout. Cancelled, failed, or limited scans discard partial results.
- **Practical large-playlist limits.** Scans are bounded at 50,000 entries, 2,000 pages, and 16 million metadata characters. Progress shows retrieved counts, elapsed time at each page, and final playlist validation.
- **Playlist consistency checks.** Available modification dates and optional version hashes are checked before and after retrieval. The popup explains when markers are missing and warns that matching markers do not prove an atomic snapshot.

## Improvements

- More defensive validation of communication between the popup and the page-context MusicKit bridge, with bounded metadata and fixed error messages.
- Node.js 22 compatibility without a version-specific test-isolation flag. Supported majors are Node 22 (22.8+), 24, and 26.
- Expanded regression coverage for deadlines, resource limits, cancellation, repeated scans, late failures, changed playlists, and unavailable or expired sessions.
- Reproducible dependency installation through `npm ci` and the committed lockfile. The unit runner now uses the existing esbuild dependency and Node's isolated test processes instead of tsx.
- Deterministic ZIP packaging, exact package-content validation, and a SHA-256 checksum file for each build.

## Security & Maintenance

- Updated esbuild and Chrome typings, with Node typings aligned to the oldest supported major.
- GitHub Actions CI for pushes and pull requests, with immutable action pins, read-only repository permissions, and no release publication step.
- Weekly full dependency vulnerability checks and Dependabot monitoring for npm packages and GitHub Actions.
- Actual unpacked-extension smoke tests covering installation, the toolbar popup, `activeTab` grants, MAIN-world injection, duplicate results, cancellation, expired sessions, and revoked permissions.
- Static checks for the production file allowlist, minimal permissions, content security policy, and selected credential patterns. Secret values are never printed by the scanner.

## Validation

The complete local verification process passed on Windows with Node 22.8.0, 22.23.4, 24.22.1, and 26.12.1. It includes TypeScript validation, 64 unit tests, 46 UI fixture scenarios, real unpacked-extension smoke tests, production builds, ZIP inspection, deterministic packaging, SHA-256/tamper checks, and static security checks. The dependency audit reported no known vulnerabilities at release preparation, and the workflow passed `actionlint`.

The maintainer also personally tested the updated extension on the live Apple Music website with approximately 1,200 songs. The scan completed, detected duplicates, and showed no visible bugs. This is a successful live test, not a guarantee for every account, region, browser, or future player version. Automated browser tests use controlled fictional fixtures and require no Apple Music credentials.

## Installation

Download `apple-music-duplicate-finder-v1.1.0.zip`, extract it into a folder you intend to keep, and load that folder using **Load unpacked** at `chrome://extensions` or `edge://extensions` with **Developer mode** enabled. Keep the folder in place. Existing users can replace the files in their installation folder and click **Reload** on the Extensions page.

The matching `apple-music-duplicate-finder-v1.1.0.zip.sha256` file verifies download integrity. See [download verification](../RELEASING.md#verify-a-download) for commands. Unpacked extensions do not update automatically.

## Known Limitations

- The browser toolbar popup closes when users click outside it. This remains intentional for v1.1.0; keep it focused while scanning. Closing it discards the scan and results.
- Apple Music does not guarantee atomic playlist snapshots. Same-count edits and reordering may escape detection, even with available metadata checks. Avoid editing a playlist during a scan.
- Extremely large or slow scans may stop at the configured limits. They show an error rather than accepting incomplete results.
- Live Apple Music compatibility can change when Apple updates its website or APIs. Broader account, region, and branded-browser testing remains useful.
- Different catalog editions remain separate, and entries without reliable identifiers are excluded from matching.
- Aborting an underlying request depends on the player API honoring the supplied signal. Otherwise, the page request may finish, but its late result cannot update a cancelled or later scan.

The permissions remain `activeTab` and `scripting`. There are no broad host permissions, analytics, telemetry, or third-party playlist uploads. No side panel or marketplace publication is included.
