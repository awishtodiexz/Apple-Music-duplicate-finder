# Apple Music Duplicate Finder v1.2.5

Feature release since v1.2.0. The extension stays read-only, keeps only the `activeTab` and `scripting` permissions, processes playlist data locally, and never removes or changes your music.

## What's new

- **Toolbar badge.** After a scan the icon shows how many songs are repeated (`999+` for very large lists). **Clear results** removes it, and opening the popup on a different playlist no longer inherits the previous count.
- **Copy a single song.** Every result row has its own **Copy** button that copies just that song's copy count and positions.
- **Minimum-copies filter.** Narrow the list to `2+`, `3+`, `4+` or `5+` copies. When a search or filter hides everything, **Clear search and filters** restores the list.
- **Keyboard search.** `/` focuses the search field, `Escape` clears it, and clearing results returns focus to the scan button.
- **Open in a window.** The popup can move into its own 400 px window pinned to the playlist tab, so a scan survives clicking elsewhere. It hides while a scan is running, because opening it would close the popup.
- **Stale-scan notice.** If Apple's modification marker changed since the cached scan, the popup says the playlist changed and offers a rescan instead of showing silently outdated results.
- **Excel-friendly CSV.** Downloads start with a UTF-8 BOM so accented and non-Latin names open correctly.

## Reliability

- Cached results are painted before Apple Music is contacted and stay visible when MusicKit is unavailable or the player is slow.
- The first scan after opening the popup reuses the connection metadata, removing one round trip.
- A scan that cannot finish inside the ten-minute deadline stops early, projected from the fastest recent page so a single retry sleep cannot trigger it.
- Playlist detection matches the playlist ID by route segments, tolerating extra name or view segments, a plural `playlists` path and trailing slashes.
- The local cache now holds a full 50,000-track result set (2.97 MB, raised limit 4.5 MB).
- A rendering error while reporting progress no longer discards a valid scan, badge failures cannot affect a scan, and modification markers are compared symmetrically.
- Injection failures caused by tab access report `TAB_ACCESS` rather than `UNEXPECTED`.

## Accessibility

- Scan progress and result counts announce through dedicated live regions: phase changes immediately, progress at most every 20 seconds, and filter counts after a short debounce. The visible status block no longer re-announces itself on every update.
- Search, sort and filter borders meet the 3:1 non-text contrast requirement in both themes.

## Validation

`npm run check` passed on Windows with Node 26.12.1: 107 unit tests, 56 browser fixture scenarios, the installed-extension smoke suite (including a real pop-out window), deterministic ZIP/checksum/tamper checks and static security checks. `npm run audit` reported zero vulnerabilities. A separate stability pass covered ten consecutive scans, double clicks, `pagehide` cancellation, corrupt caches, storage-quota failures, Chrome API failures, a 25,000-group cache restore (about 50 ms) and heap stability.

These changes are covered by controlled fixtures. Live Apple Music, branded Chrome/Edge toolbars and screen-reader speech were not independently tested for this release.

## Installation

Requires Chrome or Edge **111** or newer on desktop.

1. Download `apple-music-duplicate-finder-v1.2.5.zip` and extract it into a folder you intend to keep.
2. Open `chrome://extensions` (or `edge://extensions`) and enable **Developer mode**.
3. Choose **Load unpacked** and select the extracted folder containing `manifest.json`.
4. Pin the extension, sign in at music.apple.com, open a playlist, and scan.

Verify the download with `apple-music-duplicate-finder-v1.2.5.zip.sha256`; see [download verification](https://github.com/awishtodiexz/Apple-Music-duplicate-finder/blob/v1.2.5/docs/RELEASING.md#verify-a-download). Unpacked extensions do not update automatically.

## Known limitations

- The popup closes, and an in-progress scan is discarded, when it loses focus; use **Open in a window** first. Completed scans are cached.
- Same-count playlist edits and reordering may escape detection.
- Scans stop at the ten-minute, 50,000-entry, 2,000-page or 16-million-metadata-character limits; failed scans return no partial results. At 100 entries per page, 50,000 tracks still means 500 sequential requests.
- Duplicate groups are rendered 50 at a time; there is no virtualization for very large result sets.
- Entries without reliable identifiers are excluded, and different catalog editions remain separate.
- Apple can change its web player or MusicKit interface at any time.
