# Apple Music Duplicate Finder v1.1.2

This is a reliability hardening patch after a full source audit. It keeps the read-only toolbar popup, exact identifier-based matching, and the same two permissions. Playlist data is still processed locally, and the extension never removes or changes your music.

## Fixes and improvements

- **Transient failures are retried.** A network drop, timeout, rate-limit response, or 5xx error on one page no longer discards a long scan. The reader retries the same offset with bounded backoff (up to two retries) and still validates every page before accepting it.
- **Transient and permanent API errors are distinguished.** A new `SERVER` code covers 5xx responses, so only genuinely transient failures are retried; 4xx rejections still fail immediately with an actionable message.
- **The popup can no longer hang forever.** Page injection is bounded to 30 seconds. Previously a wedged renderer or a discarded tab could leave the popup on "Connecting..." with the button disabled and no way back except closing it.
- **Failures are reported honestly.** Unexpected errors are logged and described as an extension error instead of being blamed on tab access. A closed tab is reported as a playlist change. Permission denials keep the existing tab-access guidance.
- **The 50,000-entry limit is reachable.** The overall deadline is now ten minutes instead of five, matching the documented entry limit on realistic connections. The deadline clock is also monotonic, so a wall-clock adjustment cannot extend a scan.
- **Trailing slashes no longer break a scan.** Routes are normalized before comparing the popup's playlist with the live location, so the player's URL canonicalization cannot cause a spurious "playlist changed" error.
- **Screen readers are no longer flooded.** Scan progress no longer re-announces the whole status block on every page: progress text is throttled, announcements are held while pages stream in, and unchanged text is not rewritten.
- **One source of truth for error codes.** The transport validates against a single shared list, with compile-time guards and a unit test that proves the serialized page function still matches it.
- **Single-source versioning.** The manifest version is generated from `package.json` at build time, so a release bump touches one place.
- **Hardened extension-page CSP.** Added `form-action 'none'` and `frame-src 'none'` on top of the existing `default-src 'self'`, `script-src 'self'`, `object-src 'none'`, `connect-src 'none'`, and `base-uri 'none'`.
- **Smaller bundle.** The production bundle is minified: 17 KB instead of 27 KB, which also reduces the source re-injected for every page.
- **Faster CI.** The browser, installed-extension, and packaging suites run once per operating system instead of on every Node matrix entry; typechecking and unit tests still cover Node 22.8, 22, 24, and 26. Release gating is no longer blocked by low-severity development-only advisories.
- **Package metadata.** Added repository, homepage, issues, license, and author fields.

- `npm run check` — 76 unit tests, 48 UI fixture scenarios, installed-extension smoke suite, deterministic ZIP/checksum/tamper checks, and static security checks.
- `npm run audit` — zero known vulnerabilities.

Pull-request CI (all five required checks) passed before merge. No open CodeQL or Dependabot alerts were reported at release preparation.

The matching rules, pagination acceptance rules, permissions, and popup layout are unchanged. The live Apple Music test recorded for v1.1.0 still applies to this scan flow; the v1.1.2 changes are covered by controlled fixtures. Edge, screen-reader speech, and additional account/region combinations still need independent live testing.

## Installation

Requires Chrome or Edge **111** or newer on desktop.

1. Download `apple-music-duplicate-finder-v1.1.2.zip` and extract it into a folder you intend to keep.
2. Open `chrome://extensions` in Chrome or `edge://extensions` in Edge.
3. Enable **Developer mode**, then choose **Load unpacked**.
4. Select the extracted folder containing `manifest.json`.
5. Pin the extension, sign in at `music.apple.com`, open a playlist, and scan.

The matching `apple-music-duplicate-finder-v1.1.2.zip.sha256` file verifies download integrity. See [download verification](https://github.com/awishtodiexz/Apple-Music-duplicate-finder/blob/v1.1.2/docs/RELEASING.md#verify-a-download). Unpacked extensions do not update automatically.

## Known limitations

- The toolbar popup closes when focus is lost, including clicking outside it. Keep it focused while scanning; closing it discards the scan.
- Apple Music does not guarantee atomic playlist snapshots. Same-count edits and reordering may escape detection even with available metadata checks.
- Very large or slow scans may still stop at the ten-minute, 50,000-entry, 2,000-page, or 16-million-metadata-character limits. Failed or limited scans accept no partial results.
- Different catalog editions remain separate, and entries without reliable identifiers are excluded from matching.
- Aborting an underlying request depends on the player API honoring the supplied signal. A late result cannot update a cancelled or later scan.
- Apple can change its web player and MusicKit interface; live compatibility may change.

The permissions remain `activeTab` and `scripting`. There are no broad host permissions, analytics, telemetry, or third-party playlist uploads. No side panel or marketplace publication is included.
