# Apple Music Duplicate Finder v1.4.0

Bug-fix release since v1.3.0. The extension remains read-only, keeps only the `activeTab` and `scripting` permissions, processes playlist data locally, and never removes or changes your music. Duplicate matching is unchanged.

## What's fixed

- **Per-tab toolbar badge.** The duplicate count is shown only on the tab that was scanned. Previously the badge was extension-global, so every other tab and playlist showed the last scan's count until the popup was reopened.
- **No false "changed during scanning" failure in a long-open window.** Playlist details fetched when the popup connects are reused as the scan's starting snapshot only for 30 seconds. An **Open in a window** window left open while you edit the playlist now scans normally instead of failing with `INCOMPLETE`.
- **Results stay visible during a rescan.** The previous completed results, your search and your sort stay on screen, marked busy, until the new scan completes. A failed or cancelled rescan still keeps them, labelled as the previous scan. **Clear results** is unavailable while a scan runs.
- **Keyboard focus is kept.** Focus moves from **Scan** to **Cancel scan** when a scan starts and back to **Scan** when it ends or is cancelled, and after **Retry connection**, instead of being lost to the page.

## Compatibility

- Your theme choice and last completed cached scan are preserved after updating from v1.3.0. The `amdf:theme:v1` and `amdf:last-scan:v1` storage keys and the version 1 cache schema are unchanged.
- After updating, a badge left over from v1.3.0 may remain until the next scan or popup open on that tab.

## Validation

`npm run check` passed on Windows with Node 26.13.1: **161 unit tests**, **77 browser fixture scenarios** (six new regression scenarios, three per API version), the installed-extension smoke suite (now asserting the per-tab badge and an empty global badge), deterministic ZIP/checksum/tamper checks and static security checks. `npm run audit` reported zero vulnerabilities. Each fix's regression test was observed failing before its fix.

These checks use controlled fixtures. Live Apple Music, branded Chrome/Edge toolbars and screen-reader speech were not independently automated for this release; the manifest declares Chrome and Edge 111 or newer as the manual compatibility floor.

## Installation

Requires Chrome or Edge **111** or newer on desktop.

1. Download `apple-music-duplicate-finder-v1.4.0.zip` and extract it into a folder you intend to keep.
2. Open `chrome://extensions` (or `edge://extensions`) and enable **Developer mode**.
3. Choose **Load unpacked** and select the extracted folder containing `manifest.json`.
4. Pin the extension, sign in at music.apple.com, open a playlist, and scan.

Verify the download with `apple-music-duplicate-finder-v1.4.0.zip.sha256`; see [download verification](https://github.com/awishtodiexz/Apple-Music-duplicate-finder/blob/v1.4.0/docs/RELEASING.md#verify-a-download). Unpacked extensions do not update automatically; to update, replace the extracted folder and choose **Reload** on the extensions page.

## Known limitations

- The popup closes, and an in-progress scan is discarded, when it loses focus; use **Open in a window** first. Completed scans are cached.
- Same-count playlist edits and reordering may escape detection when Apple supplies no usable marker.
- Scans stop at the ten-minute, 50,000-entry, 2,000-page or 16-million-metadata-character limits; failed scans return no partial results.
- Only the most recent completed scan is cached; scanning another playlist replaces it.
- Entries without reliable identifiers are excluded, and different catalog editions remain separate.
- A per-tab badge can remain on a tab after Apple Music switches to another playlist within the page; it is cleared the next time the popup opens there.
- Apple can change its web player or MusicKit interface at any time.
