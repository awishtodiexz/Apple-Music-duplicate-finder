# Apple Music Duplicate Finder v1.2.0

Feature release built from a full audit backlog. The extension stays read-only, keeps only the `activeTab` and `scripting` permissions, processes playlist data locally, and never removes or changes your music.

## What's new

- **A real results view.** Search by song or artist, sort by playlist order, most copies, song or artist, and see how many extra copies each group represents.
- **Copy and CSV.** Copy the visible list or download it as CSV, honouring the current search and sort.
- **Your last scan survives.** Reopening the popup restores the last completed scan, restored from bounded local storage and never uploaded. **Clear results** removes it.
- **Large groups stay readable.** Groups with more than 50 positions collapse to "1, 2, …and N more" until you expand them, and the list loads 50 groups at a time.
- **Theme control.** The header switches between **Auto** (follows your system), **Light** and **Dark**, and remembers the choice.
- **Diagnostics.** The popup footer shows the extension version, and failures show a stable error code.
- **Retry scan.** After a recoverable failure the button reads **Retry scan** instead of silently reverting.

## Reliability

- Transient failures (network, timeout, 429, 5xx) retry with bounded backoff, honouring a bounded `Retry-After` when Apple sends one.
- Permanent 4xx responses still fail immediately; a `SERVER` code separates them from network failures.
- Unknown page-side failures are reported as internal errors and never retried.
- Tab-access failures are classified from tab state rather than English error text, so localized browsers get the right guidance.
- MusicKit counts accept numeric strings, nested error shapes are handled, and every page's totals and continuation offsets are validated before it is accepted.
- "Playlist changed" now also covers a closed tab.

## Performance

`npm run benchmark` measures the CPU side of a scan:

- 1,000 tracks: 10 page calls, read 1 ms, match 0 ms
- 10,000 tracks: 100 page calls, read 1 ms, match 2 ms
- 50,000 tracks: 500 page calls, read 5 ms, match 12 ms; 25,000 groups render to an 833 KiB CSV in 12 ms

Filtering and sorting now run once per render instead of once per batch, and "Show more" no longer re-sorts the full list. No API concurrency was added: scans remain sequential and network-bound.

## Validation

`npm run check` passed on Windows with Node 26.12.1: 97 unit tests, 56 browser fixture scenarios, the installed-extension smoke suite, deterministic ZIP/checksum/tamper checks and static security checks. `npm run audit` reported zero vulnerabilities.

These changes are covered by controlled fixtures and a real Chromium build of the popup. Live Apple Music, branded Chrome/Edge toolbars and screen-reader speech were not independently tested for this release.

## Installation

Requires Chrome or Edge **111** or newer on desktop.

1. Download `apple-music-duplicate-finder-v1.2.0.zip` and extract it into a folder you intend to keep.
2. Open `chrome://extensions` (or `edge://extensions`) and enable **Developer mode**.
3. Choose **Load unpacked** and select the extracted folder containing `manifest.json`.
4. Pin the extension, sign in at music.apple.com, open a playlist, and scan.

Verify the download with `apple-music-duplicate-finder-v1.2.0.zip.sha256`; see [download verification](https://github.com/awishtodiexz/Apple-Music-duplicate-finder/blob/v1.2.0/docs/RELEASING.md#verify-a-download). Unpacked extensions do not update automatically.

## Known limitations

- The popup closes, and an in-progress scan is discarded, when it loses focus. Completed scans are cached.
- Same-count playlist edits and reordering may escape detection.
- Scans stop at the ten-minute, 50,000-entry, 2,000-page or 16-million-metadata-character limits; failed scans return no partial results. At 100 entries per page, 50,000 tracks still means 500 sequential requests.
- Duplicate groups are rendered 50 at a time; there is no virtualization for very large result sets.
- Entries without reliable identifiers are excluded, and different catalog editions remain separate.
- Apple can change its web player or MusicKit interface at any time.
