# Testing

## Automated checks

Install dependencies with `npm ci`, then install Playwright's pinned Chromium as described in [Development](DEVELOPMENT.md):

```sh
npx --no-install playwright install chromium
npm run check
npm run audit
```

The expanded suites contain **64 unit tests**, **46 browser fixture scenarios**, and an installed-extension smoke suite. They cover:

- Exact identifier matching, missing/conflicting identifiers, original order, and 10,000-entry inputs.
- Pagination beyond 100 entries, exact page boundaries, short pages, changing totals, and final metadata validation.
- Legacy `api.get()` and v3 `api.music()` response shapes, timeouts, failed HTTP wrappers, and errors after partial retrieval.
- Popup progress, recovery, safe text rendering, unknown-identity warnings, and batches of results.
- Icon paths and dimensions, keyboard focus, and document scrolling down to 300 × 300 pixels in light and dark modes.
- The 50,000-entry boundary, metadata/page budgets, overall deadlines during metadata/pages/final validation, prompt cancellation, late replies, and independent concurrent scans.
- Reordering, replacing, renaming, adding, and removing entries via changed metadata markers, and explicit unverified-consistency status when markers are absent.
- Exact ZIP contents, version alignment, deterministic bytes, checksum validation, tampered-archive rejection, minimal permissions, CSP, and targeted credential-pattern checks.

Browser fixtures use mocked Apple Music responses and a Chrome API adapter. They exercise the bundled popup and serialized page function, but do not install the extension or test the toolbar's permission grant. Screenshots generated by the runner are saved in ignored `artifacts/`. The README image uses fictional demo data; it is not evidence of a real-account scan.

`npm run test:extension` separately installs the actual unmodified production `dist/` extension into a fresh persistent Chromium profile. Chromium DevTools loads it and invokes its real toolbar action. The test attaches to the actual popup target, with no Chrome API adapter: it verifies denied injection before invocation, the `activeTab` grant, MAIN-world MusicKit communication, pagination and matching, expired authentication, changed API formats, cancellation/rescan, and revoked permissions after cross-origin navigation. All website responses are controlled fixtures; external page requests are blocked. The temporary profile is removed after the test.

CI is configured to run all checks on Node 22.8.0 and current Node 22/24/26 on Linux, plus Node 24 on Windows. The test runner compiles with the existing esbuild dependency and uses Node's default file isolation, without `--test-isolation` or tsx. Fixture success does not prove full live Apple Music or branded-browser compatibility.

### Local implementation verification (2026-10-27)

A clean `npm ci` succeeded. The complete `npm run check` passed on Windows under Node **22.8.0**, **22.23.4**, **24.22.1**, and **26.12.1**, with the unit runner's actual child runtime recorded and checked. Each run included all 64 unit tests, 46 UI fixture scenarios, the actual unpacked-extension smoke suite, the production build, ZIP/content/checksum verification, and static security checks. Browser tests used pinned Chromium 156.0.8078.4 with fictional data and no real Apple Music account.

GitHub-hosted workflow execution and Linux execution were not performed in this worktree; those remain to be verified when the workflow is run. ## Manual checks

Use a browser that permits unpacked extensions and your own Apple Music session. Record the browser and extension versions, expected counts, and results. Keep account details out of reports.

| Check | Expected result |
| --- | --- |
| Open the popup on a playlist | The displayed name matches the open playlist |
| Scan a small playlist with known repeated songs | Appearance counts and one-based positions match the playlist |
| Scan a playlist with no repeats, or a valid empty playlist | Clear result with no repeated songs |
| Scan more than 100 entries | All expected entries are retrieved; the count agrees when Apple supplies a total |
| Browse a long results list | Every loaded result is reachable; Show more adds the next batch |
| Retry after a connection failure | A successful retry displays fresh results; a failed scan accepts no partial results |
| Cancel while metadata or a track page is loading, then rescan | Immediate cancelled state, no partial results, and a fresh scan unaffected by a late reply |
| Review a playlist without modification markers | The popup explicitly warns that same-count edits/reordering cannot be detected |
| Close the popup and reopen it | The previous scan is discarded and the current playlist is detected again |
| Use a keyboard and both color schemes | Controls and results are readable and reachable |

Test Chrome and Edge separately. For real authentication, network, rate-limit, unavailable-track, and concurrent-edit failures, record only the fixed error shown by the popup and redacted reproduction steps. Do not share raw MusicKit objects, network captures, tokens, cookies, or private playlist URLs.

Live testing must also confirm whether each player generation honors the v3 fetch AbortSignal, whether modification dates/version hashes advance on real edits, and whether shared/catalog/library playlists behave consistently across regions. These behaviors cannot be established by fixtures, and require the account owner's permission.

## Live evidence and limits

For v1.1.0, the maintainer personally reports that the updated extension completed a live Apple Music scan of approximately 1,200 songs, detected duplicates, and showed no visible bugs. This does not verify every account, region, browser, playlist type, or failure condition. Edge, screen-reader speech, and additional account configurations still need independent live testing. Passing fixtures is not proof of universal Apple Music compatibility.

- Apple's web player may change its MusicKit interface.
- Different catalog editions remain separate, and entries without reliable IDs are excluded from matching.
- Without an Apple-supplied total, completion is based on API exhaustion rather than an independently verified count.
- Concurrent same-count edits can escape detection without modification metadata. Avoid editing a playlist during a scan.
- The extension does not remove or edit music.

See [Architecture](ARCHITECTURE.md) for the retrieval and identity rules, and [SECURITY.md](../SECURITY.md) for vulnerability reporting.
